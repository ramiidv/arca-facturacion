# @ramiidv/arca-facturacion

> TypeScript SDK for ARCA (formerly AFIP) electronic invoicing in Argentina.
> Wraps WSFEv1, WSFEX, and WSAA SOAP web services.

## What this SDK does

- Authenticates against ARCA's WSAA using X.509 certificates (PKCS#7/CMS signing)
- Creates electronic invoices (facturas), credit notes, and debit notes via WSFEv1
- Handles all comprobante types: A, B, C, E, M, and MiPyME FCE
- Auto-calculates IVA, totals, and comprobante numbers
- Queries ARCA parameters (document types, IVA rates, currencies, exchange rates, etc.)
- Export invoices via WSFEX (Factura de Exportación)
- Safe emission: emissions are never retried; uncertain outcomes throw `ArcaResultadoIncierto` (resolved with `recuperarComprobante`) or `ArcaResultadoInciertoExpo` (resend with the same WSFEX `Id`)
- CAEA contingency reporting with `CbteFchHsGen` (RG 5782)
- Retry with exponential backoff on transient errors (queries only)
- Persistent WSAA access tickets (`ticketStorage`) and clock-skew correction
- Event system for logging/debugging (auth, requests, retries)
- QR code URL generation for printed invoices

## Install

```bash
npm install @ramiidv/arca-facturacion
```

Requires Node.js >= 18. Uses native `fetch` (no axios/node-fetch dependency). Published as dual ESM + CommonJS (works with `import` and `require`, including TypeScript `"module": "CommonJS"`). Depends on `@ramiidv/arca-common` ^0.4.0 (WSAA, SOAP transport, validators).

**Production TLS:** WSFEv1/WSFEX production (`servicios1.afip.gov.ar`) negotiates 1024-bit DH, which Node >= 17 rejects (`ERR_SSL_DH_KEY_TOO_SMALL`). With `legacyTls: "auto"` (default) the SDK retries that handshake with arca-common's legacy `node:https` transport (`SECLEVEL=1`) and remembers the host; `"always"` uses it from the start; `"never"` disables it (production WSFEv1 then fails on Node >= 17). A custom `config.fetch` gets no fallback.

## Quick start

```typescript
import fs from "fs";
import { Arca, CbteTipo, IvaTipo, DocTipo, Moneda } from "@ramiidv/arca-facturacion";

const arca = new Arca({
  cuit: 20123456786,
  cert: fs.readFileSync("./cert.crt", "utf-8"),
  key: fs.readFileSync("./key.key", "utf-8"),
  production: false,
});

const result = await arca.facturar({
  ptoVta: 1,
  cbteTipo: CbteTipo.FACTURA_B,
  items: [{ neto: 1000, iva: IvaTipo.IVA_21 }],
});
// result: { aprobada: true, cae: "...", cbteNro: 42, importes: { total: 1210, neto: 1000, iva: 210, ... } }
```

## Architecture

The SDK has two API levels:

1. **Simplified API** (`facturar`, `notaCredito`, `notaDebito`) — auto-calculates IVA, totals, comprobante number, dates. Returns a clean `FacturaResult`.
2. **Raw API** (`crearFactura`, `crearFacturaAuto`) — maps 1:1 to AFIP's WSFEv1 SOAP methods. Returns raw AFIP XML responses parsed to JS objects.

Internally:
- `Arca` (main class) — orchestrator, holds config, exposes all methods
- `WsaaClient` (from `@ramiidv/arca-common`) — WSAA authentication, ticket cache/storage, clock skew
- `WsfeClient` / `WsfexClient` — WSFEv1 / WSFEX SOAP calls via arca-common's `afipSoapCall` (`qualified: true`, SOAPAction = namespace + method). Request fields are serialized in WSDL sequence order.
- `facturacion.ts` — pure functions for IVA/total calculation and invoice building
- `qr.ts` — QR URL (`generarUrlQR`, `urlQRDesdeFactura`)
- `errors.ts` — `ArcaWSFEError` (extends `ArcaServiceError`), `ArcaResultadoIncierto`, `ArcaResultadoInciertoExpo`; base errors from arca-common

## Configuration

```typescript
new Arca({                   // ArcaConfig extends ArcaBaseConfig (@ramiidv/arca-common)
  cuit: number | string,      // CUIT, with or without hyphens. Check digit validated (ArcaValidationError)
  cert: string,               // X.509 certificate PEM content
  key: string,                // Private key PEM content
  production?: boolean,       // Default: false (uses homologación/testing endpoints)
  tokenTTLMinutes?: number,   // Default: 720 (12 hours)
  timeout?: number,           // Default: 30000 (30 seconds). `requestTimeoutMs` = deprecated alias
  loginErrorCooldownMs?: number, // Default: 60000. Wait after a failed WSAA login
  fetch?: typeof fetch,       // Custom fetch for every request (proxy, mTLS, tests)
  legacyTls?: "auto" | "never" | "always", // Default "auto" (see Production TLS)
  endpoints?: { wsaa?, wsfe?, wsfex?, padronA5?, padronA13? }, // Custom service URLs
  retries?: number,           // Default: 1. Queries only (timeout, network, 5xx). Emissions are NEVER retried.
  retryDelayMs?: number,      // Default: 1000. Exponential backoff: delay * 2^(attempt-1).
  onEvent?: (event: ArcaEvent) => void, // Callback for all SDK events
  paramCacheTTLMs?: number,   // Default: 86400000 (24h). 0 disables parameter cache. Puntos de venta and cotizaciones are never cached.
  ticketStorage?: TicketStorage, // Persist WSAA tickets across restarts. Strongly recommended.
  clockOffsetMs?: number,     // ARCA clock - local clock (ms). Default: 0. Also used for default invoice date.
  autoClockSkew?: boolean,    // Default: true. Auto-adjust offset if WSAA rejects login due to clock.
  signal?: AbortSignal,       // Global cancellation for every call of this instance.
  wsaa?: WsaaClient,          // Shared WSAA client (e.g. with ArcaPadron). `arca.wsaa` exposes this instance's client.
})
```

Without `ticketStorage`, a restart loses the access ticket and WSAA rejects new logins ("ya posee un TA válido") until the old one expires (up to 12h) → `ArcaTicketVigenteError`. Use `FileTicketStorage(dir)` or implement `TicketStorage { get(key), set(key, ticket), delete?(key) }` over your DB. `AccessTicket` is plain JSON (ISO dates).

Every public method accepts an optional last argument `{ signal?: AbortSignal }`, combined with the config `signal`.

## Safe emission (no ambiguous states)

| Outcome | SDK result | Issued? |
| --- | --- | --- |
| Authorized | `FacturaResult` with `aprobada: true`, `cae` | yes |
| Rejected | `ArcaWSFEError` (Errors) or `aprobada: false` (Resultado "R") | no (see 10016) |
| Unknown (timeout, dropped connection, HTTP 5xx, unreadable response, abort after sending, ARCA internal errors 500/501/502) | `ArcaResultadoIncierto` | must be resolved |

- Emissions (FECAESolicitar, FECAEARegInformativo, FECAEASinMovimientoInformar, FEXAuthorize) are never retried.
- `ArcaResultadoIncierto` + `recuperarComprobante` cover facturar, notaCredito, notaDebito, crearFactura, registrarFacturaCAEA, registrarCAEA.
- Exports (facturarExpo, crearFacturaExportacion): uncertain outcome (incl. WSFEX internal errors 500/501/502/505 and responses without FEXResultAuth) throws `ArcaResultadoInciertoExpo` with `id`, `cbteTipo`, `ptoVta`, `cbteNro`, `intento: { id, cbteNro, fecha }` and `request` (the exact Cmp). Per the WSFEX manual ("Manejo transaccional"), resend with the SAME Id: `facturarExpo({ ...opts, ...err.intento })` or `crearFacturaExportacion(err.request)`. If it was already authorized WSFEX returns the original CAE with `Reproceso="S"` → `result.reproceso === true`.
- `sinMovimientoCAEA`: uncertain outcome is `ArcaSoapError` with `uncertain: true`; check with `consultarSinMovimientoCAEA` before resending.
- No connectivity (DNS failure, connection refused) is NOT uncertain: `ArcaSoapError` with `uncertain: false` (nothing was sent).
- `ArcaResultadoIncierto` has `intento: IntentoComprobante` (`{ ptoVta, cbteTipo, cbteNro, importeTotal, docTipo, docNro, fecha }`), `intentos` (all invoices of the request) and `operacion`.
- `arca.recuperarComprobante(intento)` returns:
  - `{ estado: "no_emitido" }` if last authorized < cbteNro → retrying with the SAME cbteNro is safe.
  - `{ estado: "autorizado", resultado: FacturaResult }` if FECompConsultar matches ImpTotal (±0.01), DocTipo, DocNro, CbteFch.
  - `{ estado: "conflicto", encontrado: FECompConsultarResult }` otherwise.
- Pass `cbteNro` explicitly to make retries idempotent: ARCA rejects a number already used (error 10016), so a duplicate can never be issued. Without `cbteNro` the SDK uses last + 1 with no lock: serialize emissions per (ptoVta, cbteTipo).
- `arca.armarComprobante(opts & { cbteNro })` (or the pure `armarComprobante` function) returns `{ request, importes, intento }` without network: persist `intento` before sending so a crashed process can recover.
- Validation 10016 arrives as `aprobada: false` with that observation. The manual uses 10016 both for "CbteDesde is not last + 1" (after a previous attempt it usually means that attempt WAS authorized → `recuperarComprobante`) and for "CbteFch out of range" (nothing to recover: fix the date). `requiereRecuperacion(resultOrError)` distinguishes by the message: false if it only mentions the date, true if it mentions the number or is ambiguous ("El numero o fecha ...").
- Pin `fecha` in the opts you persist: otherwise `armarComprobante` and `facturar` could compute different dates around midnight.

```typescript
const opts = { ptoVta: 1, cbteTipo: CbteTipo.FACTURA_B, cbteNro: 151, fecha: formatDate(arca.wsaa.now()) /* @ramiidv/arca-common */, items: [{ total: 1210, iva: IvaTipo.IVA_21 }] };
const { intento } = arca.armarComprobante(opts);
await db.save({ estado: "enviando", opts, intento });
try {
  const res = await arca.facturar(opts);
  if (!res.aprobada && requiereRecuperacion(res)) { /* 10016: resolve with recuperarComprobante(intento) */ }
} catch (e) {
  if (e instanceof ArcaResultadoIncierto) {
    const r = await arca.recuperarComprobante(e.intento);
    if (r.estado === "autorizado") { /* r.resultado.cae */ }
    else if (r.estado === "no_emitido") { await arca.facturar(opts); /* same cbteNro */ }
    else { /* conflicto: manual review, r.encontrado */ }
  }
}
```

## Simplified API — facturar()

Automatically: gets next comprobante number, calculates all totals from line items, formats dates in Argentina timezone, defaults to Consumidor Final + Pesos + Productos.

```typescript
interface FacturarOpts {
  ptoVta: number;                          // Punto de venta
  cbteTipo: number;                        // CbteTipo enum
  cbteNro?: number;                        // Explicit number: skips ultimoComprobante, makes retries safe
  items: LineItem[];                       // Line items (see below)
  descuentoGlobal?: number;                // Final amount (IVA included), prorated across aliquots, exento and no gravado
  cbtesAsoc?: ComprobanteRef[];            // Associated comprobantes ({ tipo, ptoVta, nro, cuit?, fecha? }; cuit check digit validated)
  periodoAsoc?: { desde, hasta };          // PeriodoAsoc: only NC/ND (not FCE), instead of cbtesAsoc
  actividades?: number[];                  // Actividades (see getActividades)
  concepto?: number;                       // Default: PRODUCTOS, or SERVICIOS if `servicio` provided. 2/3 REQUIRE servicio; 1 rejects it
  docTipo?: number;                        // Default: DocTipo.CONSUMIDOR_FINAL (99)
  docNro?: number;                         // Default: 0. docTipo 80/86 → check digit validated
  condicionIva?: number;                   // CondicionIva enum. REQUIRED if docTipo != 99 (not inferred). Defaults to 5 for docTipo 99. Class A requires docTipo != 99 and an A-valid condition (10243)
  canMisMonExt?: "S" | "N";                // Optional. "S" only with foreign currency (10241)
  fecha?: Date | string;                   // Default: today (ARCA clock, Argentina timezone). "YYYYMMDD" or "YYYY-MM-DD", must exist
  servicio?: { desde, hasta, vtoPago };    // Required for concepto 2/3. Date or "YYYYMMDD"; desde <= hasta
  moneda?: string;                         // Default: "PES"
  cotizacion?: number;                     // > 0. PES → must be 1 (10039). Foreign → required unless canMisMonExt "S" (10038)
  tributos?: Tributo[];                    // Importe/BaseImp >= 0, rounded to 2 decimals; <Tributos> omitted if empty
  opcionales?: Opcional[];                 // E.g., CBU for FCE: [{ Id: "2101", Valor: "..." }]
}

// Exactly one of `neto` (without IVA) or `total` (final price, IVA included).
type LineItem =
  | { neto: number; iva?: number; exento?: boolean }
  | { total: number; iva?: number; exento?: boolean };
// iva: IvaTipo enum. If set, item is "gravado".
// exento: true → ImpOpEx. Neither → ImpTotConc (no gravado). For exento/no gravado, total = neto.
```

`CondicionIVAReceptorId` is mandatory per RG 5616: ARCA rejects invoices without it from 01/12/2026 (WSFEv1 manual v4.8). The SDK requires `condicionIva` when the receiver is identified (a CUIT can be RI, monotributo or exento); use `condicionIvaDesdePadron` from `@ramiidv/arca-padron`.

**IVA calculation rules:**
- Items with `iva` set → added to ImpNeto. IVA calculated using IVA_RATES and added to ImpIVA. Grouped by aliquot in the Iva array.
- Items with `exento: true` → added to ImpOpEx.
- Items with neither → added to ImpTotConc (no gravado).
- ImpTotal = ImpNeto + ImpIVA + ImpOpEx + ImpTotConc + ImpTrib.
- `total` items: base = round(total / (1 + rate)), IVA = total - base (exact).
- `descuentoGlobal` is prorated by group final amount; the rounding remainder goes to the group with the largest base. Tributos are not discounted.
- Computed in integer cents: sum(BaseImp + Importe) + ImpOpEx + ImpTotConc + ImpTrib == ImpTotal exactly.
- For CbteTipo C (monotributista): IVA is NOT discriminated. All items go to ImpNeto, ImpIVA = 0.

**Return type:**

```typescript
interface FacturaResult {
  aprobada: boolean;
  cae?: string;
  caeVencimiento?: string;    // "YYYYMMDD"
  cbteNro: number;
  ptoVta: number;
  cbteTipo: number;
  importes: {
    total: number;
    neto: number;
    iva: number;
    exento: number;
    noGravado: number;
    tributos: number;
    descuento?: number;
  };
  observaciones: { code: number; msg: string }[];
  eventos: { code: number; msg: string }[];   // ARCA `Events` (general notices)
  fecha?: string; docTipo?: number; docNro?: number; moneda?: string; cotizacion?: number;
  tipoCodAut?: "E" | "A";                     // CAE or CAEA (for the QR)
  raw: FECAESolicitarResult | FECompConsultarResult;  // FECompConsultar when obtained via recuperarComprobante
}
```

## Simplified API — notaCredito() / notaDebito()

Same as `facturar` but with `comprobanteOriginal` instead of `cbteTipo`. The NC/ND type is inferred automatically (FACTURA_B → NOTA_CREDITO_B, etc.).

```typescript
await arca.notaCredito({
  ptoVta: 1,
  comprobanteOriginal: { tipo: CbteTipo.FACTURA_B, ptoVta: 1, nro: 150 },
  items: [{ neto: 100, iva: IvaTipo.IVA_21 }],
});

await arca.notaDebito({
  ptoVta: 1,
  comprobanteOriginal: { tipo: CbteTipo.FACTURA_A, ptoVta: 1, nro: 200, fecha: "20260301" },
  docTipo: DocTipo.CUIT,
  docNro: 30712345671,
  condicionIva: CondicionIva.RESPONSABLE_INSCRIPTO,
  items: [{ neto: 500, iva: IvaTipo.IVA_21 }],
});
```

Export (class E) NC/ND are issued through WSFEX: `notaCredito`/`notaDebito` with a FACTURA_E original throw `ArcaValidationError` → use `facturarExpo({ cbteTipo: CbteTipo.NOTA_CREDITO_E, cbtesAsoc })`. `facturar` also rejects class E types.

**Supported CbteTipo mappings (WSFEv1):**
- FACTURA_A (1) → NC_A (3), ND_A (2)
- FACTURA_B (6) → NC_B (8), ND_B (7)
- FACTURA_C (11) → NC_C (13), ND_C (12)
- FACTURA_E (19) → NC_E (21), ND_E (20) — in the maps for reference only; issue them with facturarExpo
- FACTURA_M (51) → NC_M (53), ND_M (52)
- FCE_FACTURA_A (201) → FCE_NC_A (203), FCE_ND_A (202)
- FCE_FACTURA_B (206) → FCE_NC_B (208), FCE_ND_B (207)
- FCE_FACTURA_C (211) → FCE_NC_C (213), FCE_ND_C (212)

## Raw API (advanced)

Maps directly to WSFEv1 SOAP methods. No auto-calculation. User must provide all fields.

```typescript
  PtoVta: 1,
  CbteTipo: CbteTipo.FACTURA_B,

    Concepto: 1, DocTipo: 99, DocNro: 0,
    CbteDesde: nextNum, CbteHasta: nextNum,
    CbteFch: "20260328",
    ImpTotal: 121, ImpTotConc: 0, ImpNeto: 100,
    ImpOpEx: 0, ImpTrib: 0, ImpIVA: 21,
    MonId: "PES", MonCotiz: 1,

// Or with auto-numbering (still no auto-calc)
```

## Input validation

The SDK validates inputs before sending to ARCA, throwing `ArcaValidationError` (extends `ArcaError`, with `field` and `details`):
- `facturar()` / `notaCredito()` / `notaDebito()` / `armarComprobante()`: ptoVta, cbteTipo (not class E), cbteNro (integer >= 1), items (exactly one of neto/total, >= 0, no iva+exento, known aliquot), descuentoGlobal (0..total), fecha / servicio / cbtesAsoc[].fecha / periodoAsoc (existing dates via arca-common), concepto vs servicio, moneda/cotizacion/canMisMonExt (10038/10039/10241), docNro CUIT check digit, class A receiver (10243), tributos (Importe/BaseImp/Alic >= 0). **condicionIva required when docTipo != 99.**
- `facturarExpo()`: ptoVta, cbteTipo (19/20/21), tipoExpo (1/2/4), cliente, moneda, cotizacion > 0, formaPago, pais, items; Permiso_existente/permisos per the manual table (1720); fechaPago only for type 19 (1673) and >= fecha for services (1674).
- `crearFactura()` / `registrarCAEA()`: PtoVta, CbteTipo, invoices not empty, Imp* finite, CbteDesde/Hasta, CbteFch (YYYYMMDD, existing), FchServ* format, MonId, MonCotiz (unless CanMisMonExt "S"), CondicionIVAReceptorId when DocTipo != 99; registrarCAEA also requires CAEA and CbteFchHsGen (yyyymmddhhmmss).

## Error handling

```typescript
import {
  ArcaAuthError, ArcaTicketVigenteError, ArcaWSFEError, ArcaSoapError,
  ArcaResultadoIncierto, ArcaResultadoInciertoExpo, ArcaValidationError, ArcaServiceError,
} from "@ramiidv/arca-facturacion";

try {
  await arca.facturar({ ... });
} catch (e) {
  if (e instanceof ArcaResultadoIncierto) {
    // Unknown outcome of an emission: resolve with arca.recuperarComprobante(e.intento)
  }
  if (e instanceof ArcaResultadoInciertoExpo) {
    // FEXAuthorize unknown outcome: resend with the same Id (e.intento / e.request)
  }
  if (e instanceof ArcaWSFEError) { // extends ArcaServiceError
    // ARCA business error: NOT issued
    e.errors; // { code: number, msg: string }[]
    e.tieneCodigo(600);  // internal ARCA errors 500/501/502 come as ArcaResultadoIncierto instead
  }
  if (e instanceof ArcaValidationError) {
    e.field; e.details; // nothing was sent
  }
  if (e instanceof ArcaTicketVigenteError) {
    // WSAA already issued a valid TA that is not in memory/storage: wait until it expires
  }
  if (e instanceof ArcaAuthError) {
    // WSAA login failed (bad cert, expired, etc.)
  }
  if (e instanceof ArcaSoapError) {
    // HTTP/SOAP transport error in a query, or an emission certainly not sent (uncertain: false)
    e.statusCode; e.faultString; e.uncertain; e.aborted;
  }
}
```

All error classes extend `ArcaError` which extends `Error`, and have a stable `code`
("ARCA_RESULTADO_INCIERTO", "ARCA_RESULTADO_INCIERTO_EXPO", "ARCA_WSFE_ERROR", "ARCA_VALIDATION_ERROR", "ARCA_TICKET_VIGENTE", "ARCA_AUTH_ERROR", "ARCA_SOAP_ERROR").
`instanceof` works across duplicated copies of the package (ESM + CJS in the same process).

## Events / Logging

Two ways to subscribe:

```typescript
// 1. Config callback (receives all events)
const arca = new Arca({
  ...,
  onEvent: (e) => console.log(e.type, e),
});

// 2. Typed .on()/.off() (filter by event type)
arca.on("request:end", (e) => console.log(`${e.method} took ${e.durationMs}ms`));
arca.on("auth:login", (e) => console.log(`Login ${e.service} in ${e.durationMs}ms`));
arca.on("request:retry", (e) => console.warn(`Retry #${e.attempt}: ${e.error}`));
```

Event types (discriminated union `ArcaEvent`):
- `auth:login` — new token obtained. Fields: `service`, `durationMs`
- `auth:cache-hit` — cached token reused. Fields: `service`
- `request:start` — SOAP call starting. Fields: `method`, `endpoint`
- `request:end` — SOAP call completed. Fields: `method`, `durationMs`
- `request:retry` — retrying after error (queries only). Fields: `method`, `attempt`, `error`
- `request:error` — request failed. Fields: `method`, `error`

## Retry

Enabled by default (`retries: 1`) for queries only (incl. WSAA login and padrón). Retries on timeout, network errors and HTTP 5xx without SOAP Fault. Does NOT retry SOAP Faults, 4xx, business errors, or any emission. Exponential backoff: `retryDelayMs * 2^(attempt-1)`.

## QR Code URL

ARCA requires a QR code on printed invoices. Per the current ARCA spec: base URL `https://www.arca.gob.ar/fe/qr/` (`QR_URL`, overridable with `{ baseUrl }`), JSON v1 with `fecha` "YYYY-MM-DD", numeric 14-digit `codAut`, and `tipoDocRec`/`nroDocRec` only "de corresponder" (omitted when undefined).

```typescript
// From a FacturaResult (facturar / notaCredito / notaDebito / registrarFacturaCAEA / recuperarComprobante)

const url2 = Arca.generateQRUrl({ // or generarUrlQR(input, options?)
  fecha: "20260328",      // YYYYMMDD, YYYY-MM-DD or Date → sent as YYYY-MM-DD
  cuit: 20123456786,
  ptoVta: 1,
  tipoCmp: CbteTipo.FACTURA_B,
  nroCmp: 150,

  ctz: 1,
```

## WSFEX (Export invoices)

Simplified API (`facturarExpo`) auto-handles ID, numbering (both overridable with `id`/`cbteNro` for resends), `Imp_total`, `Fecha_pago` (type 19 services/otros only; defaults to the invoice date) and `Permiso_existente` (`"S"`/`"N"`, default `"N"`, only for Factura E 19 + tipoExpo 1; empty for NC/ND E and services/otros). The Cmp is serialized in WSDL order.

```typescript

  cliente: {

    domicilio: "123 Main St, NY",
    idImpositivo: "12-3456789",
  },
  moneda: "DOL",
  cotizacion: 1200,
  formaPago: "Wire Transfer",
  incoterms: "FOB",
  idioma: 2,  // 1=ES, 2=EN, 3=PT
  items: [{
    codigo: "SKU001",
    descripcion: "Widget",
    cantidad: 100,
    unidad: 7,
    precioUnitario: 10,
    // Pro_total_item auto-calculated: 100 * 10 = 1000
  }],
});
```

## CAEA (offline/contingency invoicing)

CAEA (Código de Autorización Electrónico Anticipado). Since RG 5782 (WSFEv1 manual v4.6) CAEA is a contingency-only mode: every CAEA point of sale is a contingency one, must share a domicile with a CAE point of sale (or fiscal controller), and every reported comprobante carries `CbteFchHsGen` (generation date+time, yyyymmddhhmmss) — mandatory (error 1440).

```typescript
// 1. Request CAEA for a fortnight (periodo YYYYMM, orden 1|2; validated)
const caea = await arca.solicitarCAEA("202611", 1);
// caea: { CAEA, Periodo, Orden, FchVigDesde, FchVigHasta, FchTopeInf, FchProceso, eventos }

// 2. Report each comprobante issued offline (same interface as facturar() + fechaHoraGeneracion)
const result = await arca.registrarFacturaCAEA(caea.CAEA, {
  ptoVta: 5,
  cbteTipo: CbteTipo.FACTURA_B,
  cbteNro: 120,
  fechaHoraGeneracion: new Date("2026-11-03T14:32:10-03:00"), // REQUIRED → CbteFchHsGen (Argentina time)
  // fecha?: defaults to the date of fechaHoraGeneracion (never the reporting date)
  items: [{ neto: 100, iva: IvaTipo.IVA_21 }],
});
// Returns FacturaResult with cae = CAEA and tipoCodAut "A"

// 3. Points of sale without movement
await arca.sinMovimientoCAEA(caea.CAEA, 6);            // sends PtoVta, CAEA (WSDL order)
await arca.consultarSinMovimientoCAEA(caea.CAEA, 6);   // [{ CAEA, FchProceso, PtoVta }]

// Query existing CAEA
const existing = await arca.consultarCAEA("202611", 1);

// Raw API: registrarCAEA({ PtoVta, CbteTipo, invoices: [{ ...detail, CAEA, CbteFchHsGen }] })
```

## Key domain concepts

- **CUIT**: Argentine tax ID (11 digits, no hyphens). Used for business identification.
- **Punto de venta (PtoVta)**: Sales point number (1-99999). Must be pre-registered with ARCA.
- **CAE**: Código de Autorización Electrónica. Unique code ARCA returns for each approved invoice.
- **Comprobante**: Generic term for any fiscal document (factura, nota de crédito/débito, recibo).
- **WSFEv1**: ARCA's SOAP web service for electronic invoicing.
- **WSAA**: ARCA's authentication web service. Uses CMS/PKCS#7 signed tickets.
- **Homologación**: ARCA's testing/sandbox environment. Use `production: false`.
- **FCE MiPyME**: Factura de Crédito Electrónica for small/medium businesses. Requires CBU in opcionales.
- **Tipo C**: Invoices issued by monotributistas (simplified tax regime). No IVA discrimination.
- **WSFEX**: ARCA's web service for export invoices. Separate from WSFEv1, different schema.
- **CAEA**: Código de Autorización Electrónico Anticipado. Since RG 5782, contingency-only; reports require CbteFchHsGen.
- **Padrón A13 / Constancia de inscripción**: ARCA's taxpayer registry web services. A13 = basic info (name, status, address). Constancia de inscripción (`ws_sr_constancia_inscripcion`, former A5, which is deprecated) = address and registered taxes. Each requires separate WSAA authorization.
